# mirrorfs

`mirrorfs` is a Linux FUSE filesystem. It shows one local directory and, in the
background, replays mutations made through the mount onto a second directory
(intended to be an NFS mount).

It is not a sync tool. It does not scan either tree, and it does not reconcile
files that already differ.

## Semantics

The local directory is the only source of truth.

- Reads (`read`, `readdir`, `getattr`, `lookup`, `readlink`, `statfs`, xattr
  reads) go only to the local directory. The remote directory is never
  consulted for a read, even when the local object is missing.
- `<mount>/sys` is not part of that directory. It is a small virtual tree
  (`stats`, `queue`, `errors`) generated by the mount. It is not copied to
  the remote. A local object named `sys` at the top of `--local` is hidden
  for the life of the mount.
- Every mutation is applied to the local directory first. The FUSE call returns
  as soon as that local call succeeds, or returns the local error if it fails.
- The same mutation is then appended to a persistent FIFO queue and applied to
  the remote directory by one background thread.
- File handles opened through the mount refer only to local files. The remote
  directory is never held open.
- Metadata changes (`chmod`, `chown`, `utimens`, `setxattr`, `removexattr`,
  and the rest of `setattr`) use the same path: local first, then queue.
  `rename`, `link`, `symlink`, and `fallocate` do too. `getxattr` and
  `listxattr` are local reads.
- Out-of-band changes are not detected and are not queued. A lookup still
  reads the local directory, because that directory is the source of truth, so
  a file written directly under `--local` can show up on a later lookup.
  Nothing compares the two trees, and a file that exists only on the remote is
  never served.
- If a queued mutation needs a remote object that mirrorfs has not already
  created or copied, the worker first writes a full copy of the local object
  (file bytes or symlink target, mode, uid, gid, timestamps, and xattrs) and
  only then applies the mutation. Parent directories are created as needed so
  the copy has somewhere to land. Sibling files are not copied. Copying a
  directory copies that directory only, not the names inside it. A later
  mutation of a path that has already been created or copied does not snapshot
  it again when it is queued. If the remote apply then fails while that
  directory is still reachable, the worker repairs the path from the live
  local object, as described below.

The queue is a hidden directory, `.mirrorfs-queue/`, inside the local
directory. That name is not listed or looked up through the mount, and it is
not copied to the remote. Each record is a file named with a monotonic
sequence number. Records are fsynced and renamed into place, and the queue
directory itself is fsynced, so a crash or restart keeps every operation that
had been accepted. The worker deletes a record only after the remote call
succeeds. A remote outage leaves the record in place and retries it with
backoff. If the remote directory can still be stated and the call fails,
the worker copies the corresponding local object onto the remote and
applies the operation again. Order is preserved: a later record is not
applied before an earlier one.

On `SIGINT`, `SIGTERM`, or unmount, mirrorfs stops accepting FUSE calls,
tries to finish the record it is currently applying, and leaves any remaining
records on disk for the next start.

## Build

### Build dependencies

Compiling needs a Rust toolchain that satisfies `rust-version` in
`Cargo.toml` (1.85 or newer) and these Debian or Ubuntu packages:

| Package | Why |
| --- | --- |
| `build-essential` | C toolchain used by Cargo build scripts |
| `pkg-config` | Locates the FUSE headers when a dependency asks for them |
| `libfuse3-dev` | FUSE 3 headers. Runtime linking does not use this library |
| `fuse3` | Provides `fusermount3`, used to mount and unmount |
| `dpkg-dev` | Provides `dpkg-deb` and `dpkg-shlibdeps` for the `.deb` |

```sh
sudo apt-get install build-essential pkg-config libfuse3-dev fuse3 dpkg-dev
```

Rust can come from rustup and stay in the user account. No boot-time service
or kernel setting is required. The kernel still has to provide `/dev/fuse`,
which a normal Linux kernel does.

### Release binary

```sh
cargo build --release --locked
```

When the registry cannot be reached and `Cargo.lock` is already populated:

```sh
cargo build --release --locked --offline
```

The binary is `target/release/mirrorfs`. It is dynamically linked against
`libc.so.6` and `libgcc_s.so.1` only. It talks to the kernel through
`/dev/fuse` and runs `fusermount3` for mount and unmount. It does not link
`libfuse`.

### Debian package

`packaging/build-deb.sh` builds the release binary and packs it as
`dist/mirrorfs_<version>-<revision>_<arch>.deb`. The package version follows
`Cargo.toml` plus the Debian revision in that script (currently `0.1.0-6`).
The package installs `/usr/bin/mirrorfs`, `man mirrorfs`, and
`man fuse.mirrorfs`. Library dependencies are filled in by
`dpkg-shlibdeps`. `fuse3` is added as well, because `fusermount3` is executed
by name and is not a shared library.

```sh
packaging/build-deb.sh
```

Offline, on a machine that already has the lockfile dependencies cached:

```sh
MIRRORFS_CARGO_OFFLINE=1 packaging/build-deb.sh
```

Install it on another machine with apt so the dependencies are pulled in:

```sh
sudo apt-get install ./dist/mirrorfs_0.1.0-6_amd64.deb
```

`dpkg -i` does not install dependencies. Install them first, then the package:

```sh
sudo apt-get install fuse3 'libc6 (>= 2.39)' libgcc-s1
sudo dpkg -i mirrorfs_0.1.0-6_amd64.deb
```

The `.deb` built here is amd64 and needs glibc 2.39 or newer (`GLIBC_2.39`).
That matches Debian 13 and Ubuntu 24.04. Debian 12 and Ubuntu 22.04 are older
than that and cannot run this binary. The installed command is
`/usr/bin/mirrorfs`. The package does not change `/etc/fuse.conf`, does not
add a user, and does not install a service.

Runtime dependencies declared by the package:

| Package | Why another system needs it |
| --- | --- |
| `libc6` (>= 2.39) | The binary is linked against glibc |
| `libgcc-s1` | The binary is linked against `libgcc_s.so.1` |
| `fuse3` | `fusermount3`, FUSE device setup, and the libfuse library that `fusermount3` itself uses |

`libfuse3-dev` is only needed to compile. It is not a dependency of the
`.deb`. On Debian 13 the library package pulled in by `fuse3` is
`libfuse3-4`. Older Debian and Ubuntu releases name that library
`libfuse3-3`. Depending on `fuse3` covers both.

## Mount

```sh
mirrorfs --local /mnt/claude_local --remote /mnt/claude_remote /mnt/claude
```

| Option | Meaning |
| --- | --- |
| `--local PATH` | Local directory. Reads and the accepted state come from here. |
| `--remote PATH` | Directory that receives the asynchronous mirror. It can be the root of a mount or a folder inside one. |
| `--remote-fs TYPE` | Kernel filesystem type that directory must be on, such as `nfs`, `cifs`, or `ceph`. `nfs` also matches `nfs4`. Repeat the flag, or join types with `:`. |
| `--remote-check DURATION` | How often to look for `--remote-fs` while it is absent. `30s`, `5m`, `1h`. Default `5m`. Requires `--remote-fs`. |
| `--remote-rate RATE` | How fast the background copier may write to the remote. `32M`, `8M`, or a byte count. `K`/`M`/`G` are multiples of 1024. Default `32M`. `0` removes the cap. |
| `--debug`, `-d` | Log every operation: path, name, result, and whether it was queued. |
| `--allow-other` | Pass FUSE `allow_other`. |
| `MOUNTPOINT` | Existing empty directory to mount on. |

This form stays in the foreground and logs to the terminal. Unmount with
`fusermount3 -u MOUNTPOINT`, or send `SIGINT` / `SIGTERM`.

`--debug` writes lines like:

```text
mirrorfs op=write path=notes.txt result=ok queued=yes
```

### Mounting from /etc/fstab

With the package installed, `/usr/bin/mirrorfs` is on the default `PATH`.
`mount -t fuse.mirrorfs` runs `mount.fuse3`, which executes `mirrorfs` with
the local directory, the mount point, and `-o`. That form daemonizes: the
parent waits until the mount exists, then exits, so boot does not stay
blocked on the filesystem. Do not put `foreground` in fstab. That option
keeps the process in the foreground and `mount` would wait forever.

```fstab
/mnt/claude_local  /mnt/claude  fuse.mirrorfs  remote=/mnt/claude_remote,remote-fs=nfs,remote-check=5m,allow_other,nodev,nosuid,_netdev,nofail,x-systemd.requires-mounts-for=/mnt/claude_local  0  0
```

The first field is the local directory. `remote=` is the directory that
receives the mirror. It can be the mount root or a folder inside that mount.
`remote-fs=nfs` accepts a kernel type of `nfs` or `nfs4`. Until the path is
on that filesystem, mirrorfs stays mounted, queues mutations, and does not
copy them onto the local directory underneath the mountpoint. A check thread
looks again every `remote-check` interval (default 5 minutes) and drains the
queue once the type matches. Copies then go through a directory fd held on
that mount, so a later unmount cannot redirect them onto the local disk.
The copier thread runs at nice 19 and in the idle I/O class, and it writes
to the remote at `remote-rate` (default 32 MiB/s). The threads that serve
the mount are unchanged. One second of credit is allowed after the copier
has been idle, and sustained writes then stay at the cap. Set
`remote-rate=0` to remove the cap, or `remote-rate=8M` to leave more of the
host for the container. While the cap holds the copy back, `queue_depth` in
`sys/stats` rises and `<local>/.mirrorfs-queue/` holds the backlog.

Leave `x-systemd.requires-mounts-for=` off the remote path. With it, systemd
does not start mirrorfs when the NFS mount has failed. Keep it for the local
directory. `allow_other` lets other accounts use the mount. As root, that
does not need `user_allow_other` in `/etc/fuse.conf`. `nodev` and `nosuid`
are passed through to the kernel. `_netdev` orders the mount after the
network. `nofail` lets boot continue when this mount fails. Paths cannot
contain a comma, because mount options are comma-separated. The type seen by
`remote-fs` is the one `findmnt -n -o FSTYPE` prints. `cifs` is the kernel
name of an SMB mount, and `ceph` is the kernel Ceph client.

The same line by hand:

```sh
sudo mount -t fuse.mirrorfs /mnt/claude_local /mnt/claude -o remote=/mnt/claude_remote,remote-fs=nfs,remote-check=5m,allow_other,nodev,nosuid
```

A folder inside each mount, rather than the mount roots:

```sh
mirrorfs \
  --local /mnt/claude_local/projects \
  --remote /mnt/claude_remote/projects \
  --remote-fs nfs \
  --remote-check 5m \
  /mnt/projects
```

Unmount with `umount /mnt/claude` or `fusermount3 -u /mnt/claude`. The
daemon logs to `/var/log/mirrorfs.log`. If that file cannot be opened, the
log is discarded. `debug` on the option list writes one line per operation
there. `man mirrorfs` and `man fuse.mirrorfs` describe the command and this
fstab line. `auto_unmount` is rejected.

### Mounting as root for other users

`allow_other` lets accounts other than the mounter use the filesystem. The
kernel still enforces each file's mode, owner, and group (`default_permissions`).
A file or directory created by another account is owned by that account on
the local tree and on the remote.

As root, `/etc/fuse.conf` does not need `user_allow_other`:

```sh
sudo mirrorfs \
  --local /mnt/claude_local \
  --remote /mnt/claude_remote \
  --allow-other \
  /mnt/claude
```

From a source checkout that has not been installed, use
`target/release/mirrorfs` in place of `mirrorfs`.

As a non-root user, `fusermount3` rejects `allow_other` unless
`/etc/fuse.conf` contains a line `user_allow_other`. This repo does not change
that file. Without the flag, the mount is private to the user who started it.

## Queue directory

Location: `<local>/.mirrorfs-queue/`.

| Entry | Role |
| --- | --- |
| `NNNNNNNNNNNNNNNNNNNN.op` | One queued operation. Lowest number is applied next. |
| `*.op.tmp` | A record still being written. Ignored until it is renamed. |
| `NNNNNNNNNNNNNNNNNNNN.blob` | Sparse copy of a file larger than 8 MiB. Removed when that copy record is finished. |
| `base.log` | Paths mirrorfs has already created or fully copied on the remote, so later mutations do not snapshot the file again. |

A file of 8 MiB or less is stored, with its attributes, inside its `.op`
record. A larger file is copied into a sibling `.blob` before the queue lock
is taken, in 1 MiB chunks, skipping holes (`SEEK_DATA` / `SEEK_HOLE`). The
record itself stays small. The worker replays that blob the same way and does
not read the live file for that copy, so a later mutation cannot change the
bytes of an earlier snapshot. Known paths are kept in memory and rebuilt from
record headers on startup, so a mutation does not read record bodies to
decide whether a copy is needed. `<mount>/sys/stats` counts records without
reading them. A repair of any other operation streams the live local object
in the same chunks. An exchange is repaired by copying both local names and
leaving them there: applying the exchange afterwards would swap them back.
A plain rename moves the remote source when it is still present, so the
names inside a directory move with it, and copies the local destination
only when that source is gone.

While the worker is retrying, new FUSE calls still complete against the local
directory and append to the queue.

## Status files

`mirrorfs` does not publish kernel sysfs entries. The same information is a
directory at the mount root. It is omitted from directory listings, including
`ls -a`. Opening the path still works, and the files inside are listed once
the directory is open:

```text
<mount>/sys/stats
<mount>/sys/queue
<mount>/sys/errors
```

| File | Contents |
| --- | --- |
| `stats` | `uptime_ms`, `fuse_ok`, `fuse_errors`, `remote_ok`, `remote_retries`, `queue_depth` |
| `queue` | One line per record still waiting: sequence number, then the operation. Empty when nothing is queued. |
| `errors` | Remote apply failures and queue read or append failures. The newest 64 distinct messages are kept. Repeating the latest message refreshes its timestamp instead of adding a line. |

`fuse_errors` counts FUSE results other than success, including an ordinary
miss such as `ENOENT`. `remote_retries` counts attempts that left the record
queued. A failure that the worker repaired is listed in `errors` with
`recovered` and is not added to `remote_retries`. The directory is mode
`0555` and the files are mode `0444`, owned by the user who mounted the
filesystem. The kernel then denies writes with
`EACCES`. A change that reaches mirrorfs, such as removing the directory,
returns `EROFS`. Creating the name `sys` at the mount root fails because that
directory is already there.

## Known limitations

- One way only. Remote edits are not pulled back, and pre-existing differences
  are not bulk-copied. The first mutation of an unknown path copies that
  object only.
- Once a path is in `base.log`, a later mutation does not snapshot it again
  at enqueue time. If applying that mutation fails while the remote
  directory can still be stated, the worker copies the live local object
  over the remote path and applies the queued operation once more. A queued
  copy is replayed from the bytes stored in the record. An exchange copies
  both local names and does not swap them again. A plain rename moves the
  remote source when that source still exists. Unlink and rmdir remove a
  conflicting remote node, including a non-empty directory at that path.
  Copying a directory still copies that directory only, not the names inside
  it. If the remote root cannot be stated, or the copy fails (permissions,
  a full disk), the record stays queued and the worker backs off from 200ms
  up to 5s. The repair copies the live local file in 1 MiB chunks, skipping
  holes, without the lock that covers FUSE writes, so a write that arrives
  during the copy can race it.
  The queued mutation is still applied afterwards, and later records run
  in order.
- A replayed create or write gets its timestamps when the remote call runs.
  A snapshot stores the local timestamps, and the write queued after that
  snapshot then updates the remote file mtime. An explicit timestamp change
  is stored in the queue as the resulting value and applied as that value.
- Missing parent directories are created from the local directory's mode,
  owner, and timestamps. After a create or copy, ancestor directories owned
  by the mounter are stamped from the local directory again, because adding
  the child updates the directory mtime. A parent owned by someone else is
  left unchanged.
- The first mutation of a file the remote does not yet have copies that file.
  Up to 8 MiB stays in the queue record. A larger file is streamed sparsely
  into a `.blob` beside the queue and replayed from there in 1 MiB chunks.
  The queue directory needs room for that blob until the copy finishes.
  Filesystems without hole seeks are copied densely, still one chunk at a time.
- Queue order is global, not per file. A retrying record holds up later
  records until it succeeds.
- `chown` to a uid other than the mounter needs root (or `CAP_CHOWN`). If it
  fails, the failure is retried, which stalls the queue until it can succeed.
- Extended attributes that the remote filesystem rejects with `ENOTSUP` are
  logged and skipped so one unsupported xattr cannot wedge the mirror.
  `fallocate` is skipped the same way when the remote returns `ENOTSUP`.
- A plain rename of a path mirrorfs already knows (the path itself, or a
  file inside it) is replayed with `rename`. If that record is applied twice,
  the second attempt sees the source gone and the destination present and
  treats that as success. `RENAME_EXCHANGE` is not idempotent: applying it
  twice swaps the names back. NFS rejects the exchange flag, so the worker
  swaps the two remote objects with three renames through a temporary name,
  `.mirrorfs-exchange`, in the destination's parent. A crash between those
  renames is finished on the next attempt. A crash after the swap, before
  the record is deleted, swaps them again.
- An exchange where mirrorfs does not yet know both sides copies the local
  object at each exchanged path instead of renaming. A directory copy does
  not include the names inside it, so children that were already mirrored
  stay at their old remote path.
- `RENAME_WHITEOUT` is rejected with `EOPNOTSUPP` and is not applied locally.
- POSIX byte-range locks, `ioctl`, and `copy_file_range` are not implemented.
  The kernel falls back to plain reads and writes for copies.
- Inode records for names seen during the mount are cached until `forget` or
  unmount.
- The mount does not follow paths that escape the local root. `.mirrorfs-queue`
  is hidden, not a security boundary against someone who can already write the
  local directory directly. `<mount>/sys` is reserved and is omitted from
  directory listings: a local object of that name at the root is not visible
  through the mount, and the virtual directory is reachable only by path.

applies the oldest `.mirrorfs-queue/` record to the remote directory and
deletes it only after that call succeeds. A remote error leaves the record in
place and retries it, including after the process is killed. A mutation of a
path mirrorfs has not already created or copied is preceded by a snapshot of

locally and queued the same way. A rename of a tree mirrorfs already knows
moves that tree on the remote. A rename of a path it does not know copies
the local object at its new path. `<mount>/sys/stats`, `sys/queue`, and
`sys/errors` report counters, the records still waiting, and recent remote
or queue failures. A remote error while that directory is still reachable
is repaired by copying the local object and applying the operation again.
